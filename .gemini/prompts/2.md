Atue como um Engenheiro de Software Sênior e especialista na estruturação de workspaces do Antigravity CLI. 

Sua tarefa exclusiva neste momento é inicializar o nosso ambiente de desenvolvimento configurando o diretório `.agents/`. Não escreva nenhum código do site principal ainda. Crie estritamente os diretórios e arquivos listados abaixo com seus respectivos conteúdos.

### 1. Crie a Estrutura de Diretórios
Crie os seguintes diretórios na raiz do projeto:
* `.agents/`
* `.agents/docs/plans/`
* `.agents/Skills/`
* `.agents/Rules/`

### 2. Crie o arquivo `.agents/CONTEXT.md`
Preencha o arquivo com o texto exato abaixo:

# Contexto do Projeto
## Identidade
Aplicação Web Mobile-First, utilizando Astro e Tailwind CSS. Foco extremo em UX/UI responsivo, performance, estado da arte em design (micro-animações, glassmorphism) e acessibilidade.

## Arquitetura
- **Framework:** Astro (SSG focado em performance, ilhas de hidratação parciais quando necessário).
- **Estilização:** Tailwind CSS (Utility-first, paletas de cores não genéricas, HSL).
- **Linguagem:** TypeScript estrito.
- **Testes:** Vitest + Testing Library (TDD é estritamente obrigatório).

## Git Flow
- `main`: Código em produção (deployável).
- `develop`: Código de integração.
- `feature/*`: Novas funcionalidades (ramificadas da `develop`).
- `bugfix/*`, `release/*`, `hotfix/*`: Fluxos secundários.

## Execução via Antigravity CLI
- Todos os passos devem ser guiados pelos arquivos em `docs/plans/`.
- Subagentes (`self` ou especializados) podem ser invocados para paralelizar tarefas como revisão de UX ou testes.

### 3. Crie os Arquivos de Skills em `.agents/Skills/`
Crie um arquivo `.md` para cada item abaixo e use a descrição como conteúdo instrucional do arquivo:

* `git-flow-manager.md`: Atue como Especialista em versionamento. Crie branches apropriadas (feature/, hotfix/), realize commits semânticos (Conventional Commits), e gerencie os PRs e merges da develop para a main.
* `astro-component-builder.md`: Focado em construir a estrutura dos componentes .astro. Domine a separação entre lógica server-side (frontmatter) e templates HTML5 semânticos.
* `tailwind-styler.md`: Domine UX/UI avançado. Transforme wireframes em interfaces "Wow", usando variáveis globais de CSS, tipografia moderna (Inter, Outfit), gradientes e responsividade mobile-first.
* `tdd-vitest-runner.md`: Focado na lógica reversa do TDD (Red-Green-Refactor). Crie o .spec.ts, execute o teste até falhar, reporte, e valide a implementação feita pelo builder.
* `ux-ui-reviewer.md`: Perfil de subagente para auditar a interface gerada, avaliando contraste, áreas de toque (mobile) e fluidez das animações.

### 4. Crie os Arquivos de Rules em `.agents/Rules/`
Crie um arquivo `.md` para cada item abaixo e use a descrição como a regra estrita:

* `git-flow-rules.md`: Proibido commitar diretamente na main ou develop. Obriga o agrupamento lógico de arquivos por commit. O agente não deve executar push --force.
* `astro-best-practices.md`: Obrigatoriedade do uso de TypeScript (<script lang="ts">). Proibido usar diretivas client: (JavaScript no browser) em componentes estáticos; usar apenas em elementos puramente interativos.
* `tailwind-responsive-rules.md`: O desenvolvimento deve começar do tamanho menor de tela (mobile base) e escalar usando prefixos sm:, md:, lg:. Proibido CSS inline.
* `tdd-mandatory.md`: Absolutamente nenhum componente Astro ou lógica utilitária deve ser escrita antes da especificação do teste falhar.

### 5. Crie o arquivo de Planejamento `.agents/docs/master-plan.md`
Preencha o arquivo com o ciclo de desenvolvimento e as diretrizes de mitigação de gargalos abaixo:

# Planejamento do Ciclo de Prompts (6 Passos)
1. **Prompt 1 (Plan 01):** Inicializar projeto Astro (create-astro), configurar Vitest, TailwindCSS, tipografia e limpar repositório base. Iniciar develop.
2. **Prompt 2 (Plan 02):** Implementar e testar o Design System (Cores, Fontes, Botões Globais) via TDD.
3. **Prompt 3 (Plan 03):** TDD da arquitetura base (Header, Navigation Mobile, Footer, Layout Wrapper).
4. **Prompt 4 (Plan 04):** TDD das páginas de conteúdo. Consumo de dados locais ou API, focando na performance de renderização estática.
5. **Prompt 5 (Plan 05 - Refinamento):** Invocar o subagente revisor de UX. Adicionar animações, micro-interações, corrigir contraste e adequar para um visual premium (Wow effect).
6. **Prompt 6 (Plan 06 - Deploy):** Fechar branch de release, merge em main, tagear a versão e gerar build final/scripts de deploy.

# Gargalos e Pontos Críticos a Evitar
- **Context Window no TDD:** O ciclo contínuo de testes pode inundar o histórico. **Solução:** Executar comandos de teste silenciosamente e pedir o log focado apenas nas falhas atuais usando grep ou subagentes temporários.
- **Acoplamento em TDD de UI:** Testar classes exatas do Tailwind quebra facilmente. **Solução:** Focar os testes em comportamentos, acessibilidade (ARIA roles) e presença de slots.
- **Fluxo Git Autônomo:** Conflitos de merge travam o agente. **Solução:** Limitar o escopo de cada branch rigidamente para evitar edições simultâneas nos mesmos arquivos base.
