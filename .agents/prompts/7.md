# Prompt de Execução: Plan 04 - Páginas de Conteúdo (SSG)

Você é o agente encarregado de executar o **Plan 04** do `master-plan.md`. Nossa missão é dar vida às páginas principais do evento (Programação, Artistas, Sobre) usando TDD e maximizando a performance de renderização estática (SSG) que o Astro oferece.

## 🎯 Objetivos do Plan 04:
1. **Git Flow:** Fazer o merge da `feature/base-architecture` na `develop` e iniciar a branch `feature/content-pages`.
2. **Dados Locais:** Criar um "banco de dados" local simulado (ex: `src/data/mock.ts`) para alimentar a agenda do evento e a lista de artistas de forma ultrarrápida no build.
3. **TDD por Página:** Escrever testes de integração validando o roteamento e a injeção do conteúdo (Mock) nas páginas `/programacao`, `/artistas` e `/sobre`.
4. **Implementação (Zero JS):** Codificar as páginas aproveitando o `Layout.astro` criado no Plan 03. Todo o conteúdo deve ser hidratado no lado do servidor (nenhum JavaScript pesado será enviado ao cliente, garantindo score 100 no Lighthouse).

## 🧠 Skills requeridas (`.agents/skills/`):
- **`git-flow-manager`**: Para orquestrar as branches de funcionalidade.
- **`tdd-vitest-runner`**: Para garantir que nenhuma página seja criada antes de haver um teste verificando o conteúdo renderizado nela.
- **`astro-component-builder`**: Para orquestrar a injeção do mock data no Frontmatter (`---`) do Astro e usar loops JSX-like (`data.map()`) nos templates.
- **`tailwind-styler`**: Para garantir que a exibição da programação e dos artistas seja visualmente deslumbrante (Wow effect).

## 📜 Regras de Ouro (Rules):
- `tdd-mandatory.md`: Escreva os testes *Testing Library* verificando títulos e textos que deveriam vir do mock.
- `astro-best-practices.md`: Use HTML5 semântico (como `<article>`, `<section>`). Não use a diretiva `client:` pois estas páginas são puramente estáticas.
- `git-flow-rules.md`: Limite o escopo dos commits logicamente.
